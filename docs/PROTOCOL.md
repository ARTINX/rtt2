# RTT2 协议

所有多字节整数与 IEEE 754 float32 均使用小端序。CRC 为 CRC16/CCITT-FALSE：多项式 0x1021、初值 0xFFFF、不反射、最终异或 0x0000；CRC 字节也按小端序传输。

## 遥测：RTT up channel 0

版本 3，固定 70 字节：

| 偏移 | 字段 | 格式 |
| --- | --- | --- |
| 0 | 魔数 RT | 2 字节 |
| 2 | 版本 3、帧长 70 | 各 u8 |
| 4 | 发送尝试序号 | u32 |
| 8 | 板端毫秒时间戳 | u32 |
| 12 | debug_info.status | u32 |
| 16 | value1 至 value13 | 13 × float32 |
| 68 | 前 68 字节的 CRC | u16 |

状态位 0 当前表示慢速云台模式。固件每 5 ms 尝试写入一整帧；缓冲区不足时可跳过整帧，序号仍递增，接收端据此统计丢帧。

## 命令：RTT down channel 0

版本 1，总长 16 + 4N 字节，0 ≤ N ≤ 12：

| 偏移 | 字段 | 格式 |
| --- | --- | --- |
| 0 | 魔数 RC | 2 字节 |
| 2 | 版本 1、总帧长 | 各 u8 |
| 4 | 会话 ID、序号 | 各 u32 |
| 12 | 命令 ID、参数数 N | 各 u8 |
| 14 | 参数 | N × float32 |
| 14 + 4N | 此前全部字节的 CRC | u16 |

当前 cmd_id=0 为无参数 PING，cmd_id=1 为 ECHO。发送由一次用户操作触发一次；主机不会因超时自动重发。

## 执行回执：RTT up channel 1

版本 1，总长 21 + 4N 字节，0 ≤ N ≤ 12：

| 偏移 | 字段 | 格式 |
| --- | --- | --- |
| 0 | 魔数 RA | 2 字节 |
| 2 | 版本 1、总帧长 | 各 u8 |
| 4 | 会话 ID、序号 | 各 u32 |
| 12 | 命令 ID、结果码 | 各 u8 |
| 14 | 板端毫秒时间戳 | u32 |
| 18 | 返回值数 N | u8 |
| 19 | 返回值 | N × float32 |
| 19 + 4N | 此前全部字节的 CRC | u16 |

结果码：0 APPLIED、1 BAD_ARGS、2 BAD_STATE、3 UNKNOWN_CMD、4 QUEUE_FULL、5 DUP_CONFLICT。当前固件不修改 Message_Publish 的返回类型，因此内部消息队列投递失败不能立即返回 QUEUE_FULL；主机超时后标记为“结果未知”。板端保留最近 16 条会话 ID 与序号，重复命令不会再次执行；当前代码仅在 Kit-miao 实板验证了 200 条不同命令，尚未单独注入重复命令验证此机制。
